## 当前功能

| 平台 | 登录 | 后续流程 | 当前状态 |
| --- | --- | --- | --- |
| 某某宝淘宝 | 二维码图片、短信验证、独立浏览器兜底 |商品校验、预约及抢购 | 已接入 |
| 某某东 | 本地 Cookie 复用、在线校验、二维码重新登录 | 某某东商品校验、预约及抢购 | 已接入 |
| 大麦 | 二维码图片、短信验证、独立浏览器兜底 | 暂不执行抢票 | 登录已接入，抢票开发中 |

其他已实现能力：

- 某某宝淘宝、某某东、大麦 Cookie 分平台保存，过期或服务端失效后自动重新登录。
- Cookie 文件采用临时文件替换，降低程序中断造成文件损坏的风险。
- 某某宝淘宝和大麦二维码保存为本地图片，无需在无头浏览器窗口中扫码。
- 遇到短信或安全验证时，优先在命令行完成；控件不可用时打开专用浏览器窗口。
- 某某东服务器时间差只修正一次。
- 多个抢购线程共享成功状态，一个线程成功后其他线程停止继续提交。
- 外部请求设置超时并启用 TLS 证书校验。

## 运行环境

- Windows 10/11
- Python 3.11（源码运行）
- Chrome 或 Microsoft Edge（某某宝淘宝、大麦扫码登录及安全验证）

Linux 尚未完成当前版本的真实登录和打包验证，不作为本版正式支持环境。

## 运行



启动前请根据自己的合法账号和使用场景配置 `config.ini`。主要配置项包括：

- `exeUser_key`：当前程序使用的授权信息。
- `exeUser_sku`：某某东商品 SKU。
- `exeUser_user_killTime`：可选的自定义抢购时间，格式为 `YYYY-MM-DD HH:MM:SS:mmm`。
- `exeUser_Cookie`：仅用于兼容旧版本；成功登录后统一使用本地 Cookie 存储。

登录超时配置位于 `configWeb.ini`：

```ini
[taobao]
login_timeout = 180

[damai]
login_timeout = 180
```

## 使用流程

程序会先执行公告、版本、维护状态及授权校验，然后显示平台菜单：

```text
请选择登录平台：
1. 某某宝淘宝
2. 某某东
3. 大麦
请输入 1、2 或 3：
```

### 选择某某宝淘宝

完成真实某某宝淘宝登录后，程序会继续取得有效的某某东登录状态，再进入现有某某东商品预约和抢购流程。某某宝淘宝 Cookie 不会被传入某某东接口。

### 选择某某东

程序优先复用 `cookies/jd.json`，登录状态失效时重新生成某某东二维码。认证成功后进入某某东预约和抢购流程。

### 选择大麦

程序优先复用 `cookies/damai.json`，失效时重新扫码。登录成功后显示真实用户名和“大麦抢票功能正在开发中”，不会调用某某东接口，也不会模拟大麦抢票结果。

## Cookie 与隐私

登录状态默认保存在：

```text
cookies/jd.json
cookies/taobao.json
cookies/damai.json
```

请勿在日志、Issue、聊天记录或提交中公开 Cookie、短信验证码、卡密、设备标识和抓包数据。

如果仓库副本曾包含真实凭据，仅删除文件并不能使凭据失效；请同时在对应平台执行退出登录、修改密码或凭据轮换。


## 当前限制

- 工具不能保证购买成功，结果仍受库存、账号状态、网络和平台规则影响。
- 大麦目前只完成真实登录和 Cookie 管理，尚未接入商品查询、选场次、选票档或下单。
- 平台接口和风控页面可能随时变化，二维码或短信验证流程可能需要后续适配。
